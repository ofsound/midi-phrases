YouPrompt 27

So code edits can be made and will be recognized *without* changing the binaries? how does that work?

AssistantResponse

Short answer: no — C++ changes only take effect after a rebuild updates the plugin binaries. I wasn’t clear enough before; here’s how it actually works.

## What actually happens

| Step | What it does |
|------|----------------|
| You edit source/*.cpp | Changes exist only as text on disk |
| cmake --build Builds | Compiler writes new machine code into .vst3 / .component / Standalone .app |
| COPY_PLUGIN_AFTER_BUILD | Copies those bundles into ~/Library/Audio/Plug-Ins/ |
| DAW loads the plugin | It runs whatever binary is on disk (or already loaded in memory) |

There is no “hot reload” for native JUCE plugins like there is for web code. Edit → rebuild → DAW picks up the new binary (sometimes after a rescan or restart).

## Rebuild vs rescan (what I meant earlier)

Those are two different steps:

- Rebuild — required for every code change you want to hear/see in the plugin.
- Rescan — DAW refreshes its *list* of plugins (paths, new installs). Often needed the first time or if the plugin “disappears,” but not a substitute for rebuilding.

Many hosts will load the updated file in place after a rebuild if you:

- Remove the plugin from the track and add it again, or
- Restart the DAW

Some keep the old version in memory until you do that — so you might think the edit “didn’t work” even though the binary on disk is new.

## Practical workflow for you

1. I (or you) change code
2. cmake --build Builds
3. In Live/Logic: reload the plugin (re-insert on the track) or restart the DAW
4. Rescan only when installing for the first time or after moving/deleting the bundle

Standalone is the easiest loop: quit the app, rebuild, open again — you’re always loading the fresh binary.

So: I’ll keep rebuilding after edits; you’ll still need to reload the plugin in the DAW (not necessarily a full rescan) to run the new code. Sorry for the confusion on that earlier.
