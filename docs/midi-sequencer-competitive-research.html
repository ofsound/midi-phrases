What MIDI Phrases is today

MIDI Phrases is a 4-lane, variable-length phrase sequencer with 8 patterns, 8 loop-brace slots, and live MIDI switching — not a fixed-grid step sequencer or chord-driven arpeggiator.

Strengths already in the product

  • Parallel polyrhythmic lanes (each row loops independently with its own step count and timing multipliers)
  • Sectional composition: loop brace within a pattern + loop-slot recall (pattern + sub-range)
  • Performance workflow: MIDI notes 1–8 switch patterns, 9–16 switch loop slots, note 17 mutes output
  • Rich step model: probability, cycle gating, skip/mute, per-step duration/velocity/timing multiplier
  • Modern WebView editor: bulk edit, undo/redo, drag-and-drop reorder, recording, piano-roll preview
  • Solid C++ scheduling with extensive Catch2 tests (~2400 lines in tests/PluginBasics.cpp)

Original vision vs built reality

From the POC development transcript:

“Interleaves separate phrases in novel ways” — rotation, call-and-response, density, probability, section switching.

Section switching (patterns + loop braces) is implemented. Algorithmic interleaving between lanes is not — today the 4 rows simply run in parallel and merge into one MIDI stream.

Where MIDI Phrases is ahead

  1. Loop brace + loop slots — sub-pattern sectional looping within a longer phrase, recallable via MIDI. Competitors have pattern banks; few combine in-pattern sectional braces with 8 dedicated loop-memory slots.
  2. Performance-first switching — pattern + loop + mute all on low MIDI notes with pulse-boundary quantization (clean note-off handling). POLYLLOP/SEQUND have pattern MIDI switching; Phrasebox is more editor-centric.
  3. Step flip-card depth — probability + cycle gating + timing multiplier + bulk ops in a modern Svelte UI. Comparable step richness to Stochas/POLYLLOP but with a cleaner editing UX.
  4. Variable step lengths on a phrase grid — closer to Eurorack thinking than fixed 16-step grids, without requiring a full DAW piano roll.
  5. Engine quality — realtime-safe C++ scheduling with strong test coverage is a solid foundation competitors don’t always advertise.

Honest positioning: MIDI Phrases is a performance-oriented multi-lane phrase looper/composer, not yet a harmonic tool, generative engine, or full arrangement workstation. Its niche is live sectional composition of parallel monophonic phrases — if the “novel interleaving” vision lands, that niche widens significantly.

Highest-value additions (prioritized)

P0 — Table stakes / unlock DAW workflow

  • P0
    MIDI export — drag pattern/row to DAW clip, or “Export SMF”. POLYLLOP, Riffer, Cthulhu, Scaler, and Stochas all do this. Without it, MIDI Phrases is a live-only tool.
  • P0
    Scale / key lock — constrain note entry, transpose, and randomize to a scale. Essential for melodic sequencing; every serious competitor has it.
  • P0
    Wire up per-row MIDI channel UI — ui/src/MidiChannelStepper.svelte exists but is not connected; backend already supports it.
  • P0
    More host-automatable parameters — today only patternSlot is a DAW parameter (source/PluginProcessor.cpp). Pulse, swing, humanize, loop position, and row mutes should be automatable for arrangement work.

P1 — Differentiation + original vision

  • P1
    Algorithmic interleaving rules — the missing core from the POC:
    • Call-and-response (lane B only fires after lane A completes a phrase)
    • Rotation / round-robin note handoff between lanes
    • Density coupling (lane activity thins when another lane is busy)
    • Section-aware muting (auto-duck rows by rule, not just manual mute)
    This is the feature no competitor owns cleanly and matches the product name.
  • P1
    Phrase / pattern generator — constrained random fill (scale-aware, rhythm templates, density target). Phrasebox and Riffer win on inspiration today; a generator that respects MIDI Phrases’ step model would close the gap without copying Riffer’s “dice” UX.
  • P1
    Chain / conditional step logic — Stochas-style “if step X fires, force/suppress step Y” for evolving patterns without manual editing.
  • P1
    JS/C++ scheduling parity tests — ui/src/phraseSchedule.js preview can diverge from audio (probability RNG differs). Trust in the UI is critical for a sequencer.

P2 — Depth for power users

  • P2
    CC / expression lanes — per-row or global MIDI CC curves (Phrasebox’s killer feature for expressive phrases).
  • P2
    Polyphonic row option — toggle per row: monophonic (current) vs allow overlapping notes on same row.
  • P2
    Euclidean / fill tools — quick rhythmic scaffolding per row (Phrasebox, many modular tools).
  • P2
    Preset / factory pattern library — curated starter phrases by genre (Scaler’s Motions model shows content libraries drive adoption).
  • P2
    MIDI input transpose / follow — hold a chord, phrases transpose to chord tones (Phrasebox/POLYLLOP model).

P3 — Platform / ecosystem (longer horizon)

  • P3
    Standalone phrase library browser — save/load/share phrases independent of full plugin state.
  • P3
    Windows polish + AAX — POLYLLOP/Scaler serve Pro Tools users; MIDI Phrases is macOS-CI-focused today.
  • P3
    iOS / AUv3 performance UI — Riffer and Scaler have mobile; MIDI Phrases builds AUv3 but UX isn’t optimized for touch performance.

What’s lacking (honest assessment)

Product / workflow gaps

  • No harmonic intelligence — fixed MIDI pitches only; no scale, chord input, or voice leading. For melodic work, users must mentally transpose or edit in a DAW after capture.
  • No MIDI export — the single biggest workflow blocker for composition (vs live jamming).
  • Original interleaving vision unimplemented — parallel loops ≠ “interleave in novel ways.” The product name promises more than the engine delivers.
  • Monophonic-only rows — limits chordal/harmonic phrases; Phrasebox and POLYLLOP are polyphonic.
  • Hard caps — 4 rows, 64 steps/row (source/PluginProcessor.h); Phrasebox has unlimited rows/length.
  • No content — no factory presets, no phrase packs, no onboarding examples. Cold start is intimidating vs Scaler/Riffer/Cthulhu.
  • Thin DAW integration — one automatable parameter; no clip export; Ableton routing still awkward (documented workaround).

Technical / quality gaps

  • Preview vs audio mismatch on probabilistic steps (deterministic JS hash vs runtime C++ RNG).
  • Recording limitations — one row at a time, chords dropped, first note replaces row.
  • No CC output beyond note on/off/velocity.
  • No preset/program system (getNumPrograms() returns 1).

Competitive moat (what to protect and extend)

The defensible angle is live sectional composition: parallel phrases + loop braces + MIDI-triggered section changes + (future) intelligent interleaving. No competitor combines all of these.

Phrasebox owns chord-reactive piano-roll phrases; Scaler owns theory + arrangement; POLYLLOP owns polymetric parameter lanes; Stochas owns probability chains. MIDI Phrases could own “perform a composition from parallel phrases with intelligent lane interaction.”
